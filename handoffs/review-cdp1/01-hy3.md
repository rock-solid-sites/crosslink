## Blocking findings

- F1: AlreadyCurrent / Diverged classification keys part of equivalence on `source.commit` (the git commit sha), which is not a semantic property of the checkpoint content.
  Evidence: CDP-1-spec.md:466-479 (§5.3 table: AlreadyCurrent requires `source.commit == S and source.state_sha256 == state_sha256`; otherwise `head.W == W` + differing semantic identity ⇒ Diverged). Contrast CDP-1-spec.md:219-222 (§2.4: "equal W and equal state_sha256 is AlreadyCurrent, not divergence") and CDP-1-spec.md:127-131 (§1.3). Also hub_v3-excerpts.rs:163-199 (`compact_v3` emits a fresh commit object `state_bytes` is byte-identical only when the idempotency guard fires; a genesis/migration path creates a new commit with identical `state.json`).
  Why it blocks: a legitimate republish of byte-identical checkpoint content from a *different* commit sha (e.g. a second bootstrap/migrate, or a compaction whose idempotency guard did not fire) has equal `W` and equal `state_sha256` but a different `source.commit` → it is falsely classified `EqualWatermarkDifferentContent` ⇒ `Diverged`, a terminal hard-stop requiring operator intervention, instead of `AlreadyCurrent`. This is internally inconsistent with §2.4 and would hard-block valid idempotent re-publishes. Fix: define equivalence for AlreadyCurrent/Diverged as `(W, state_sha256)` only; treat `source.commit` and `payload_sha256` as provenance, not as part of equivalence.

- F2: The two normative reader descriptions disagree on the load-bearing pin/integrity cross-checks.
  Evidence: CDP-1-spec.md:641-657 (§6.2 Algorithm: every blob must satisfy `m_raw.commit != C ⇒ ProtocolMismatch` and inventory `blob_sha`/`size` mismatch ⇒ `InventoryMismatch`; same checks at lines 653-654 and the rejection matrix 6.3:699-700). CDP-1-spec.md:1210-1219 (Appendix B "normative" pseudocode) omits both the `b.commit != C` pin check and the inventory↔blob mismatch check on the manifest and on every chunk.
  Why it blocks: an implementation cut from Appendix B silently drops the single-commit pin and the inventory cross-checks — the exact TOCTOU / inventory-tear protections the design advertises as its central safety property (CDP-1-spec.md:679-689, §10 T27). The contradiction must be resolved (§6.2 must win; Appendix B corrected) before any reader code is written.

  Evidence: CDP-1-spec.md:827-836 vs CDP-1-spec.md:238,260 (constants assume decoded). `CommitRequest::validate` (client.rs:383,390) and `validate.rs:16-17` mirror *decoded* limits, so a broker that counts the base64 wire body would reject a request the client accepted. - N2: CDP-1 cannot use the generic `commit_cas`/`reconcile`; the current code enforces no watermark classification.

- N5: Ordering of a head whose `source.watermark` is `None` is undefined in §5.3.
